# 环境与工作流程衔接

[English](setup.md) · [中文](setup.zh-CN.md)

可迁移技能包自带 `requirements.txt`，以及记录完整测试环境的 `requirements_lock.txt`。测试环境为 Windows 上的 Python 3.12.14 和 Stata 19。绘图程序分别从文档规定的共同输入生成图形。随包提供模拟 CSV 用于演示接口。六估计器交错处理 DID 演示先在 Stata 中完成估计，再导出共享 CSV；其 Python 渲染器不独立估计这六个模型（包括 jwdid）。承诺全流程仅用 Python 运行之前，须检查各项操作说明中的估计依赖。

宿主研究项目统一创建一个虚拟环境，将技能包依赖安装到该环境。不要为每幅图创建新环境。锁定文件记录完整的已测试包版本；较精简的依赖文件列出直接绘图依赖。使用绘图模板不需要 PDF 提取或图库构建工具。

已验收折线系列共用一个 `scripts/_shared/line_geometry.py` 模块。将其中模板复制到其他项目时，应保留该同级目录；目录文件在 `shared_resources` 字段记录这一依赖。导入路径按脚本位置解析，而非当前工作目录。画廊在各代码目录附近保留相应代码和共享依赖。目前 C10/C11 的 Python 版本支持序列与阶段 JSON 配置；其他来源特定的配置限制仍在各自操作说明中记录。

第三方 Stata 命令见 [STATA_DEPENDENCIES.md](<../STATA_DEPENDENCIES.zh-CN.md>) 和 [stata_packages.json](../stata_packages.json)。使用统一的项目本地 ado 目录，并保留已测试的包版本或哈希。绘图程序不会自动更新全局安装的包。

Windows 示例：

```shell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r PATH_TO_SKILL/requirements.txt
```

macOS/Linux 的第二条命令使用 `.venv/bin/python`。激活新环境，或继续使用其完整 Python 可执行文件路径绘图。操作说明中简写为 `python` 的命令假定该环境已经激活。生成图使用英文标签。

## 衔接边界

1. 实证工作流程构造分析样本，运行所选估计器，并导出数据、系数、区间或协方差矩阵。
2. 本技能选择目录中的绘图模板，验证输入，在研究项目的输出目录生成图形。
3. 写作或输出同步阶段在草稿中补充标题、图注、来源署名和统计说明。

不要根据图形外观改称估计器。断点回归、折点回归、阈值条件相关关系与事件研究可能共享部分图形标记，但需要不同的上游研究设计和标签。给定的置信区间属于输入，并不是聚类计算程序。

沿用宿主工作流程既有路径。常见角色包括不可变的源数据目录、中间保存的估计结果、`output/figures` 输出位置，以及草稿的下游资源。将操作说明中的 `YOUR_PROJECT` 替换为项目绝对路径，并为包含空格的路径加引号。Stata 工作目录应保持在宿主项目内，使运行日志和诊断 CSV 保留在该项目。本技能包内部不存放生成的 PNG。独立画廊用于参考和检查，不作为数值数据来源。

## 可复现记录

保留模板标识、复制脚本的版本或哈希、精确输入、调用方式、输出路径及成功运行日志。在导出图形附近记录样本、权重、估计目标、置信水平和区间方法。两种语言均使用时，应先比较所绘数值对象，再判断图像相似性；不同绘图引擎不要求逐像素一致。


默认仅生成英文图，不再额外生成中文版成图。中英文说明页与成图语言分别管理；旧验证记录中的中文图测试属于历史验证。
