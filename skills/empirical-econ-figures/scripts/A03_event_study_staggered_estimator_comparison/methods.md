# Staggered event-study estimator comparison

[English](methods.md) · [中文](methods.zh-CN.md)

This folder is an executed **synthetic-panel demonstration**, inspired by Figure 2 of Braghieri, Levy, and Makarin, *Social Media and Mental Health* ([AER paper](https://doi.org/10.1257/aer.20211218)). It is **not** a reproduction of that paper's estimates or sample. The original analysis do-files were not available in the local source review; the [official archive](https://doi.org/10.3886/E175582V1) was identified, but its analysis files were not retrieved. Five estimator routes follow [Borusyak's method-author example](https://github.com/borusyak/did_imputation/blob/main/five_estimators_example.do); the sixth uses author-maintained [`jwdid`](https://github.com/friosavila/stpackages/tree/main/jwdid).

## Result

`estimate_all.do` runs six actual Stata estimators on one seeded synthetic panel of 300 units × 15 periods: `reghdfe`, `did_imputation`, `eventstudyinteract`, `csdid` followed by `estat event`, `did_multiplegt_old`, and `jwdid` followed by `estat event`. Treatment starts in periods 10–16. The outcome has unit and time components, a treatment effect varying by calendar period, and normal noise. The command and data definitions are in the do-file. The old de Chaisemartin–d'Haultfoeuille command is deliberate: the current `did_multiplegt` command is a wrapper with changed syntax, while the method-author example used the historical dynamic route. This demonstration uses 199 seeded bootstrap repetitions for that route.

The output audited_estimates.csv (`audited_estimates.csv`) contains 61 rows: 44 post or conventional lead estimates, 10 other pretrend tests, 5 dynamic placebo tests, and 2 normalized reference markers. Event times −5 through +5 are displayed overall. `jwdid` contributes six post-treatment values, 0 through +5. All pointwise 95% intervals in the **shared plotting table** use `b ± invnormal(.975) × se`; this makes the renderers comparable but the TWFE table interval is a normal approximation rather than its command's t-based reported interval. The dynamic estimator's `se` comes from its unit-cluster bootstrap variance; `jwdid` reports delta-method event SEs based on a unit-clustered fit. Filled markers mean the plotted 95% interval excludes zero; hollow markers mean it includes zero or marks an omitted reference. Color and shape identify the estimator.

| Estimator | Preperiod interpretation | Reference and distant leads |
|---|---|---|
| TWFE OLS | Estimated lead coefficients | −1 normalized; `K <= -6` is a single included nuisance bin, so earlier periods are not silently part of the reference. |
| Sun–Abraham | Interaction-weighted lead coefficients | −1 normalized; leads −2 through −14 enter the specification, while the last-treated cohort supplies controls. |
| Callaway–Sant’Anna | Pretrend contrasts from `estat event` | The −1 `Tm1` value is a contrast, not an imposed zero. |
| de Chaisemartin–d’Haultfoeuille | `Placebo_1` through `Placebo_5` | The −1 value is a placebo test, not an imposed zero. |
| Borusyak–Jaravel–Spiess | `pre1` through `pre5` imputation pretrend tests | The −1 value is a test, not an imposed zero. |
| Wooldridge `jwdid` | No preperiod output under default not-yet-treated controls on this all-eventually-treated panel | `estat event, window(0 5)` provides post-treatment ATT only; no −1 marker is added. |

The 61 rows are **not** 61 identically defined dynamic ATT estimates. See estimator_support.csv (`estimator_support.csv`) for displayed support and each command's reported `e(N)` where available. `csdid` and `did_multiplegt_old` did not return an `e(N)` in the exported estimation state, so that field remains missing. The full input has 4,500 unit-period rows; an estimator-specific count for every horizon is not uniformly available and is not imputed from raw relative-time counts. Horizons absent from a future real-data extraction should remain absent rather than filled with zeros. The full `jwdid` event covariance matrix is saved in jwdid_event_covariance.csv (`jwdid_event_covariance.csv`) in 0–5 event order.

## Figures and parity

- Stata manual twoway PNG (`staggered_comparison_stata.png`), PDF (`staggered_comparison_stata.pdf`), from `plot_twoway.do`. The reusable `plot_staggered_twoway` program accepts `input()`, `output()`, and optional `title()`; `run_plot_twoway.do` is its project runner.
- Python PNG (`staggered_comparison_python.png`), PDF (`staggered_comparison_python.pdf`), from `plot_python.py`, which reads the **same Stata-exported CSV** and accepts optional `--title`. It performs no independent Python estimation.
- `event_plot` hybrid PNG (`staggered_comparison_event_plot_hybrid.png`), PDF (`staggered_comparison_event_plot_hybrid.pdf`), from `plot_event_plot.do`. `event_plot` parses all six coefficient/variance matrices and produces coordinates and intervals with `savecoef noplot`; native `twoway` layers then implement the required within-estimator filled/hollow significance rule. event_plot_extracted.csv (`event_plot_extracted.csv`) preserves those package outputs. The 2021 package's direct renderer has only one marker style per series, so the final significance encoding uses native layers.

All three accepted figures have no title or bottom notes by default. Captions accompanying a publication figure must explain the synthetic sample, the estimator-specific preperiod meanings, the −1 markers, unit clustering, 95% pointwise intervals, and the non-identical estimands. The paper source's post support was only 0–2; this synthetic window through +5 does not extend that paper's evidence.

The validation report (`validation.json`) checks all 59 estimated/test rows against the hybrid `event_plot` extraction, the two omitted-reference rows, and completion markers. See the report for the observed coefficient and interval differences. The final manual, Python, and hybrid PNGs are visually checked for clipping and legend overlap after regeneration.

## Re-run and dependencies

In Stata 19, change to this template directory, then run `estimate_all.do`, `run_plot_twoway.do`, and `plot_event_plot.do` in that order. Each do-file accepts this directory's absolute path as its first argument if Stata's working directory is elsewhere. `run_plot_twoway.do` additionally accepts input CSV, output stem, and optional title; `plot_event_plot.do` accepts input CSV, output stem, optional title, and extracted-CSV path. The estimator do-file writes the seeded panel and audited table before the renderers read it. Run `plot_python.py` with the shared Python environment. Build-only validation code and full logs remain in the original work archive; gallery validation contains the numerical checks. The saved `audited_estimates.csv` permits a plotting-only rerun without re-estimating.

All renderers derive the horizontal range from present integer event times. An estimator can lack a particular horizon: neither its matrix nor its plot is padded with a zero. The input contract requires exactly two normalized references (TWFE and Sun–Abraham at −1), positive SEs for all other rows, and 95% normal intervals consistent with the supplied estimates and SEs. The archived portability check (`portability_check.json`) belongs to the earlier five-estimator version; it has not been rerun for this extension.

The project-local `packages/` contains SSC copies of `avar`, `drdid`, `did_imputation`, `eventstudyinteract`, and `did_multiplegt_old`, including their help files where supplied. Author-maintained `jwdid` source and help files are under `packages/j`; a local `hdfe.ado` copy under `packages/h` satisfies its dependency check. `avar` calls the `livreg2.mlib` Mata library; the bundled copy is exposed through `packages/l` in the estimator runner. The recorded execution also had an `ivreg2` installation in pre-existing Stata PLUS, so portability without that installation has not been independently tested. Pre-existing Stata PLUS supplied `reghdfe`, `ftools`, and `csdid` for the recorded run; install those in a project-local PLUS directory for another Stata environment. The hybrid uses a local copy of the method-author [`event_plot.ado`](https://github.com/borusyak/did_imputation/blob/main/event_plot.ado) with two narrowly documented fixes for matrix-only calls with no active `e()` state and a missing indexed coefficient macro. Both the unmodified installed and current GitHub copies, help file, and upstream GPL-3.0 license are preserved beside the patched file. dependency_manifest.json (`dependency_manifest.json`) records source paths, versions where declared, and SHA-256 hashes; event_plot_patch.md (`event_plot_patch.md`) documents the patch. No global Stata package installation was made during this task.

Execution evidence: the current estimation log (`estimate_all.log`) ends with `STAGGERED_ESTIMATION_COMPLETE` and `AUDITED_ESTIMATE_ROWS=61`. The current manual Stata log (`run_plot_twoway.log`), hybrid log (`plot_event_plot.log`), Python log (`plot_python.log`), and validation log (`validation.log`) each have completion markers and no terminal Stata error code. Validation (`validation.json`) compares all 59 package-extracted nonreference rows to the audited Stata table. The portable do-files default to the current template directory.


The normalized reference at event time −1 is displayed as a hollow circle with no confidence interval. It is not an estimated effect and is excluded from pre/post averages.
